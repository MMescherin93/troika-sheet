# Тройка! — лист персонажа (веб-приложение)

Редактируемый лист персонажа для настольной ролевой игры **«Тройка!» (Troika!)**
по правилам с сайта <https://troika.wishport.online>.

Лист повторяет официальный бланк (A4, альбомная ориентация): можно заполнять
поля прямо в браузере, распечатать или сохранить в PDF, а также подключить
лист в **Owlbear Rodeo** как расширение («модуль»).

---

## 1. Что здесь лежит

| Файл | Зачем нужен |
|---|---|
| `index.html` | Структура листа. Описывает, какие блоки есть и как они называются. |
| `styles.css` | Внешний вид: рамки, шрифты, расположение — и **правила печати**. |
| `app.js` | Вся логика: строки листа, персонажи, сохранение, кнопки. |
| `manifest.json` | Файл-описание для Owlbear Rodeo (расширение). |
| `icon.svg` | Иконка расширения в Owlbear Rodeo. |
| `README.md` | Этот файл. |

Файлы **нельзя переименовывать**: `index.html` ссылается на `styles.css` и
`app.js` по этим именам, а `manifest.json` — на `index.html` и `icon.svg`.

---

## 2. Как открыть лист на своём компьютере

1. Откройте папку `troika-sheet`.
2. Дважды щёлкните по `index.html` — он откроется в браузере.

> ⚠️ Некоторые вещи (например, кнопка «Ссылка») в режиме
> `file://` работают не везде. Для полного функционала лист лучше
> запускать через небольшой локальный сервер или сразу залить в интернет
> (см. раздел 4).

**Как сохранить в PDF:** нажмите кнопку **«Печать / PDF»** → в окне печати
выберите принтер **«Сохранить как PDF»** → параметры: *Ориентация — альбомная*,
*Масштаб — 100 %*, *Поля — нет*. Получится ровно один лист A4.

## 3. Как устроено приложение (пояснение для новичка)

### 3.1. Три файла и три роли

Веб-приложение — это просто три текстовых файла, которые браузер читает
одновременно:

* **HTML** отвечает за *что* есть на странице (заголовки, поля, кнопки).
* **CSS** отвечает за *как это выглядит* (рамки, цвета, размеры, печать).
* **JavaScript** отвечает за *что происходит* (нажатия, сохранение, переключение).

Связь между ними в нашем проекте — это **атрибут `data-field`**:

```html
<input type="text" data-field="name">
```

В `app.js` есть функция, которая находит все элементы с `data-field` и
кладёт/берёт значение по такому же пути в объекте данных персонажа:

```js
{ name: "Маршалл", skill: "7", skills: [ { name: " Стрельба", rank: "1", ... }, ... ] }
```

Путь `skills.2.name` означает: объект `skills` → третий элемент → поле `name`.
Благодаря этому, чтобы добавить новое поле, достаточно:

1. дописать пустое поле в `defaultFields()` в `app.js`;
2. добавить в `index.html` элемент с нужным `data-field`.

Никакой дополнительной «прокидывающей» код не нужен.

### 3.2. Почему строки листа создаёт JavaScript, а не HTML

На листе много одинаковых строк: 12 навыков, 4 оружия, 15 паёк, 12 ячеек
инвентаря. Если написать их руками в HTML, файл станет огромным и править
его будет тяжело. Поэтому в HTML описан только **контейнер**:

```html
<div class="skills-rows" id="skillsRows"></div>
```

А в `app.js` есть цикл `buildSkills()`, который создаёт 12 строк и каждой
проставляет `data-field` (`skills.0.name`, `skills.1.name`, …).

Хотите 15 строк навыков вместо 12? Меняете одно число в объекте `COUNTS`:

```js
const COUNTS = { skills: 15, weapons: 4, damage: 7, rations: 15, inventory: 12 };
```

Число `damage` — сколько квадратиков урона стоит в каждой строке «Оружие».

### 3.3. Где хранятся данные

Данные лежат в **localStorage** браузера — это «хранилище сайта», которое
переживает перезагрузку страницы. Ключ: `troika-sheet-v1`.

Важные особенности:

* Хранилище **привязано к сайту и к вкладке-контексту**. Если открыть лист
  внутри Owlbear Rodeo (iframe), у каждого игрока будет **своя** копия данных.
  Поэтому есть кнопка **«Ссылка»** — она упаковывает персонажа
  прямо в адрес страницы, и любой, кто откроет ссылку, увидит того же героя.
* Если браузер запрещает localStorage (приватный режим, чужой iframe), код
  не падает — приложение работает «в памяти» до перезагрузки.
* Есть **экспорт/импорт JSON** — надёжный способ перенести персонажа
  на другой компьютер или отдать мастеру.

### 3.4. Печать

Все стили печати находятся в конце `styles.css`, в блоке `@media print`:

```css
@page { size: A4 landscape; margin: 0; }
@media print {
  .no-print { display: none !important; }   /* панель кнопок не печатается */
  .sheet { transform: none !important; }    /* лист печатается в реальный размер */
}
```

На экране лист может быть уменьшен (`transform: scale(...)`), чтобы влезть
в окно. При печати этот масштаб снимается — поэтому PDF всегда получается
ровно 297×210 мм.

### 3.5. Карта файла `app.js`

| Раздел | Что делает |
|---|---|
| 1. Утилиты | `makeId`, `getPath`/`setPath`, `toast` — мелкие помощники. |
| 2. Модель данных | `defaultFields()` — структура персонажа. Здесь править поля. |
| 3. Хранилище | Чтение/запись localStorage. `mergeInto`/`normalizeFields` пропускают старые и чужие файлы, не ломая лист. |
| 4. Построение строк | Циклы, создающие однотипные строки листа. |
| 5. Форма ↔ данные | `applyToForm` (показать) и `readFromForm` (считать). |
| 6. Персонажи | Выпадающий список, создание, удаление, автосохранение. |
| 7. Кнопки | Печать, экспорт, импорт, ссылка. |
| 8. Масштабирование | `fitSheet()` — вписать лист в окно. |
| 9. Запуск | `init()` — порядок всех действий при открытии страницы. |

### 3.6. Поля, которые вписываются внутрь значков

Часть значений лежит не в обычном поле, а **внутри картинки** — так же, как на
официальном бланке:

* значение **Умения** — внутри кружка;
* значение **Выносливости** — внутри сердца;
* значение **Удачи** — внутри восьмиконечной звезды;
* **значение защиты** — внутри щита в блоке «Одежда» (столбец «Значение
  защиты» в таблице остался справочным — там напечатаны значения по правилам).

Как устроено такое поле (пример — `index.html`, Умение):

```html
<div class="stat-badge">                          <!-- задаёт размер значка -->
  <svg class="stat-icon" viewBox="0 0 40 40">     <!-- рисует контур -->
    <circle cx="20" cy="20" r="18"/>
  </svg>
  <input type="text" class="stat-input" data-field="skill">
</div>
```

Поле ввода лежит **поверх** картинки (`position: absolute; inset: 0`),
поэтому занимает ровно значок, а `text-align: center` ставит цифру
посередине. Клик по значку сразу попадает в поле, а пока в нём печатаешь,
контур подсвечивается цветом (правило `.stat-badge:focus-within`).

Размер значка — это `width`/`height` у `.stat-badge` в `styles.css`
(сейчас 17 мм). У щита размер задан в `.shield-badge` (12 × 13.8 мм —
пропорции рисунка 40 × 46 из `viewBox`).

Клетки урона в блоке «Оружие» — те же **редактируемые поля** `input.cell-input`,
что и «Ранг / Умение / Всего» в навыках: 7 клеток в ряд под подписями 1…7+,
каждую можно заполнить текстом. Путь в данных ведёт в массив
`weapons.N.damage.D` (D от 0 до 6), значения — строки.

## 4. Как выложить лист в интернет (нужно для Owlbear Rodeo)

Owlbear Rodeo открывает лист по **ссылке**, поэтому файлы должны лежать
на каком-то сайте. Самый простой и бесплатный способ — **GitHub Pages**.

### Вариант A. GitHub Pages (рекомендуется)

1. Зарегистрируйтесь на <https://github.com> (бесплатно).
2. Создайте новый репозиторий (кнопка **New**). Имя, например:
   `troika-sheet`. Поставьте галочку **Add a README file**. Нажмите **Create**.
3. На странице репозитория нажмите **Add file → Upload files** и перетащите
   все 6 файлов из папки `troika-sheet`. Нажмите **Commit changes**.
4. Откройте вкладку **Settings → Pages** (слева).
   В разделе **Build and deployment**:
   * Source: **Deploy from a branch**
   * Branch: **main**, папка: **/ (root)**
   * Нажмите **Save**.
5. Подождите 1–2 минуты. Страница станет доступна по адресу вида
   `https://ВАШ-ЛОГИН.github.io/troika-sheet/`
   (её покажут сверху в том же разделе Settings → Pages).

Проверьте: откройте `https://ВАШ-ЛОГИН.github.io/troika-sheet/index.html` —
лист должен загрузиться.

> Если ссылка открылась, но кнопки не работают — проверьте, что в адресе
> именно `index.html`, а не просто папка.

### Вариант B. Netlify Drop (без регистрации)

1. Откройте <https://app.netlify.com/drop>.
2. Перетащите папку `troika-sheet` целиком в окно браузера.
3. Через минуту вы получите ссылку вида `https://случайное-имя.netlify.app`.

Минус: адрес случайный и его легко потерять.

## 5. Как установить лист в Owlbear Rodeo

После того как файлы лежат в интернете (раздел 4):

1. Соберите ссылку на `manifest.json`. Формат простой: **адрес вашего сайта + `/manifest.json`**

   | Где лежат файлы | Ссылка для Owlbear Rodeo |
   |---|---|
   | GitHub Pages | `https://ВАШ-ЛОГИН.github.io/troika-sheet/manifest.json` |
   | Netlify Drop | `https://СЛУЧАЙНОЕ-ИМЯ.netlify.app/manifest.json` |

   Обязательно откройте её в браузере: должна показаться страничка с JSON-ом
   (имя, версия, `"popover": "index.html"`), а не 404.

   > **Не годятся** эти адреса — Owlbear Rodeo их не примет:
   > * `file:///C:/Users/.../manifest.json` — файл с диска;
   > * `http://localhost:8771/manifest.json` — работает только на вашем ПК,
   >   и то пока запущен локальный сервер;
   > * `https://github.com/ВАШ-ЛОГИН/troika-sheet/raw/main/manifest.json`
   >   и `https://raw.githubusercontent.com/...` — это кнопка **Raw**;
   >   она отдаёт файлы как простой текст, и `index.html` откроется
   >   в расширении не как страница, а как исходный код.
2. В Owlbear Rodeo откройте **Rooms** → выберите комнату → меню
   (три точки или шестерёнка) → **Extensions** (Расширения).
3. Нажмите **Load Extension** / **Add Extension** и вставьте скопированную
   ссылку на `manifest.json`.
4. Появится кнопка **«Лист персонажа»** — она открывает лист прямо
   в комнате, в отдельном окне поверх карты.

### Важно: пути в `manifest.json` должны начинаться со слэша

Owlbear Rodeo склеивает **домен сайта** и то, что написано в `popover` / `icon`.
Поэтому относительный путь `"index.html"` не работает — нужен путь
**от корня сайта**, то есть начинающийся с `/`.

Так записан официальный пример расширения Hello World в документации OBR:

```json
"action": { "icon": "/icon.svg", "popover": "/" }
```

GitHub Pages отдаёт сайт не из корня, а из папки с именем репозитория,
поэтому к пути надо прибавить имя репозитория:

```json
{
  "icon": "/troika-sheet/icon.svg",
  "action": {
    "icon": "/troika-sheet/icon.svg",
    "popover": "/troika-sheet/index.html"
  }
}
```

| Где лежат файлы | `popover` и `icon` |
|---|---|
| GitHub Pages, репозиторий `troika-sheet` | `/troika-sheet/index.html`, `/troika-sheet/icon.svg` |
| GitHub Pages, репозиторий `LOGIN.github.io` | `/index.html`, `/icon.svg` |
| Netlify Drop, Render, свой домен | `/index.html`, `/icon.svg` |

> Если оставить `"index.html"` без слэша, Owlbear Rodeo получит адрес вида
> `https://ВАШ-ДОМИНindex.html` — и вы увидите ошибку
> «Не удалось найти IP-адрес сервера …github.ioindex.html».

> Если переименуете репозиторий — поправьте эти два пути.

### Если расширение не загрузилось

| Симптом | Что проверить |
|---|---|
| «Invalid manifest» | Откройте ссылку на `manifest.json` в браузере — должен показаться JSON, а не страница 404. |
| Иконка не отображается | Путь в `manifest.json` должен быть от корня сайта: `"icon": "/troika-sheet/icon.svg"`. Файл `icon.svg` должен быть залит на тот же сайт. |
| «Не удалось найти IP-адрес сервера …github.ioindex.html» | Пути в `popover` и `icon` записаны без слэша. Нужен путь от корня сайта, например `/troika-sheet/index.html` — см. раздел выше. |
| Ошибка про `clipboard-write` | Удалите весь блок `"permissions"` из `manifest.json` — просто станет чуть менее удобная кнопка «Ссылка». |
| Лист открылся, но не сохраняет данные | Внутри Owlbear Rodeo у каждого игрока своё хранилище браузера. Используйте кнопку «Ссылка» или обменивайтесь JSON-файлами. |

> **Важно:** упомянутая ссылка на `manifest.json` должна открываться у всех
> игроков. Если вы залите файлы на закрытый/платный хостинг, игроки расширение
> не увидят.

## 6. Что можно доработать (идеи для развития)

* **Подсказки-«тултипы»** с правилами при наведении на поля.
* **Автоподсчёт**: сейчас по просьбе всё заполняется вручную; если
  захотите, в `app.js` можно добавить функцию, которая складывает
  «Ранг + Умение = Всего» автоматически.
* **Синхронизация между игроками** через Owlbear Rodeo SDK
  (`OBR.room.metadata`) — тогда все в комнате увидят одну и ту же версию.
* **Тёмная тема** и хранение настроек в localStorage.
* **Печать двух листов на один лист A4** для мелких NPC.
